# Addax 6.3.0

Addax 6.3.0 is a minor release: it overhauls how transformers are loaded, validated and parameterised, removes the built-in date variables from `addax.sh`, fixes a permanent hang when the channel capacity is smaller than the exchange batch, restores the native transformers that a regression had broken, makes the reported write counters agree with the read ones, keeps DECIMAL fractions and DATETIME text through SQLite round trips and preserves the time-of-day of a DATETIME written to an ORC string column — plus 36 dependency updates. The end-to-end suite was trimmed to the core database and file cases (20 cases) and a reproducible performance baseline harness was added.

The version is `6.3.0` rather than `6.2.1` on purpose: this release contains a new feature and a backward-incompatible change, which is a minor bump under the [versioning scheme](https://github.com/wgzhao/Addax/blob/master/README.md#-versioning-scheme).

## ⚠️ Breaking changes

### 1. `addax.sh` no longer computes date variables (#1715)

The launch script used to inject ten system properties — `curr_date_short`, `curr_date_dash`, `curr_datetime_short`, `curr_datetime_dash`, `biz_date_short`, `biz_date_dash`, `biz_datetime_short`, `biz_datetime_dash`, `biz_datetime_0_short` and `biz_datetime_0_dash`. The `biz_*` family was hard-coded to the previous calendar day, which is wrong on weekends, holidays, T+0 runs and historical fillback, and because the injected `-D` arguments came after the user's `-p` values they could not be overridden.

The computation block and the injection are gone. Date variables are now the caller's responsibility: addax-admin fills them per task business date, and a direct `addax.sh` run must pass them explicitly.

- **Migration:** pass every variable the job references with `-p`, for example `-p "-Dbiz_date_short=20260101"` (one `-D` per variable, in the same `-p` string). Unresolved placeholders are left verbatim, so a job that still references `${biz_date_short}` will put the literal text into SQL or paths after the upgrade — check every job that uses `${curr_*}` or `${biz_*}` before upgrading.
- `AGENTS.md` and `SKILL.md` now state the new contract.

## ✨ Features

### 1. Transformer loading, validation and parameter handling (#1688)

The transformer module treated configuration mistakes as per-record failures: a transformer with a missing or malformed parameter turned every row into a dirty record instead of failing the job, the user-transformer loader resolved `transformer.json` against the working directory, `dx_null_to_default` never received its parameters, `dx_pad` could hang forever on an empty padding string, and every built-in re-parsed its positional parameters on each record.

- **Named parameters.** The five built-in transformers accept a named form: `dx_substr` (`idx`, `pos`, `length`), `dx_pad` (`idx`, `flag`, `length`, `chr`), `dx_replace` (`idx`, `pos`, `length`, `str`), `dx_filter` (`idx`, `operator`, `expr`) and `dx_map` (`idx`, `operator`, `value`). For example `{"name": "dx_pad", "parameter": {"idx": 0, "flag": "l", "length": 8, "chr": "*"}}`. The old `columnIndex` + `paras` form keeps working but logs a deprecation warning once per transformer name; mixing both forms in one transformer fails at startup.
- **Startup validation.** Parameters are parsed and validated once per execution instead of once per record. A missing, unknown or contradictory parameter fails the job before any task starts, with the transformer name and the expected form, instead of producing dirty records for the whole run.
- **Compiled once.** Groovy code and regular expressions are compiled at job start. `dx_groovy` can be invoked once only, which was documented before and is now enforced.
- **User transformers.** `transformer.json` is no longer resolved against the working directory: the registry loads the transformer directories the job references, validates the class (public, non-abstract, public no-arg constructor) once, and reports the transformer name and path instead of silently skipping it. The thread context classloader is restored correctly around the load.
- `dx_null_to_default` now receives its parameters and requires `parameter.column`; `dx_pad` no longer hangs on an empty padding string.
- Records filtered by a transformer are counted separately from dirty records, so the reported numbers no longer mix the two.
- New runnable examples: `transformer_named_demo.json` and `transformer_legacy_demo.json`; `transformer_demo.json`, `transformer_groovy.json` and `transformer_null_to_default.json` were refreshed.

## 🐛 Fixes

**Data correctness**

- `sqlite` (#1706): the JDBC driver types a column from the storage class of the row it is positioned on, so a DECIMAL/NUMERIC fraction was truncated when a PK split started on an integral value, and driver 3.54.1.0 also maps DATETIME to `Types.TIMESTAMP`, which would have written TEXT values as INTEGER epoch milliseconds. The reader now types DECIMAL/NUMERIC from the declared column type and the writer binds DECIMAL/NUMERIC through `setBigDecimal` and writes `Types.TIMESTAMP` as TEXT with milliseconds, so fractional values and DATETIME text survive round trips. The reader also defaults username/password, so a job copied from the plugin template starts instead of failing before the first row.
- `hdfswriter`, `s3writer` (#1707): ORC string targets rendered every non-TIME date column as `yyyy-MM-dd`, silently truncating a DATETIME (for example a BSON date from `mongodbreader`) to a date-only string. DATE/DATETIME now render through the common column formatters (`common.column.dateFormat` / `datetimeFormat` / `timeZone`), matching the text and parquet writers; DATE stays date-only and TIME keeps its nanos-aware path. Consumers of such ORC files now see the time-of-day.
- `core` (#1673): the write side counted every record it drained from the channel, terminate marker included, so a task reported one more written record than the reader produced — a 4-task job that moved 400 rows reported `writeReceivedRecords=404`. `writeSucceedRecords` now equals `readSucceedRecords` for a job that wrote everything it read, and the three channel waits restore the thread's interrupt status and report the same `AddaxException` type instead of dropping it or throwing a bare `IllegalStateException`.
- `core` (#1664): native transformers `dx_substr`, `dx_replace`, `dx_map` and `dx_filter` were broken by a regression — they demanded Groovy code and their `columnIndex`/`paras` were silently dropped, so even the bundled `transformer_demo.json` could not run. The pre-regression semantics are restored: only the Groovy functions consume `code`/`codeFile`, every other transformer requires `columnIndex` and takes optional `paras`, and a missing `columnIndex` fails with a clear message.
- `plugin-paimonwriter` (#1679): any warehouse reached through Hadoop failed with `NoClassDefFoundError: com/google/protobuf/ServiceException` raised from the `addBlock` path, because Paimon excludes protobuf from its Hadoop dependencies and the assembled plugin carried none. `protobuf-java` (3.25.5) is now bundled the way `hdfswriter`, `hdfsreader`, `icebergwriter` and `s3writer` already do; file:// warehouses were the only working case before.

**Reliability**

- `core` (#1668): with `core.transport.channel.capacity` smaller than the exchange batch (default 32), `MemoryChannel` waited for a whole batch to fit and never enqueued anything, so the reader blocked forever and the job sat at "Total 0 records" with no error. Batches are now enqueued record by record, waiting per record for room in the queue and the byte budget, and the consumer is signalled after every record instead of on the 200 ms poll timeout. A single record larger than the byte budget fails with `OVER_LIMIT_ERROR` instead of waiting forever, and `clear()` resets the byte accounting together with the queue.
- `core` (#1670): a fail-over retry could start while the previous attempt was still writing (duplicate rows), and the wait degraded to an unbounded `join(0)` whenever the retry budget was exactly exhausted. Each attempt now runs on its own two-worker executor, and its termination is the only "attempt is over" signal, so the previous attempt is dead before a retry starts; the next task is dispatched immediately instead of on a 100 ms tick.
- `core` (#1667): plugin entry classes are resolved and validated at job start — the class must exist, extend `Reader.Job`/`Reader.Task` or `Writer.Job`/`Writer.Task`, be public, non-abstract, static when nested and declare a public no-arg constructor. A broken plugin now fails before any task starts, with the plugin name, the `plugin.json` path and the attempted class name, instead of failing mid-run with a raw stack dump.
- `core` (#1665): `job.content` is normalized from the legacy array form to a dict at parse time; a multi-element array logs a warning and the first element wins, an empty array fails fast, and the post-split task list moved to an internal key.
- Internal cleanups with no intended behavior change: the task state machine now lives in an immutable `TaskState` (#1672), the dead single-record channel API and `RecordExchanger` are gone (#1669), framework keys are read through typed `JobConfig`/`TaskConfig` views (#1666), and the unused abstractions from the never-implemented distributed mode were removed (#1663).

**Scripts, packaging and CI**

- `install_plugins.sh` (#1695): validates plugin names and versions, installs into `libs/` with staged atomic replacement and backups, restores required transitive dependencies, verifies metadata and the bootstrapped Maven archive, and adds `force`, locking, summaries, strict release checksums and interactive Maven output. Existing `lib/` installs are reinstalled under `libs/`. The same commit renames the Elasticsearch writer's template resource so template-based job generation finds `plugin_job_template.json`.
- Distribution (#1719): `dorisreader` was missing from the root `package.xml`, so `-Pdistribution` produced a tree without `plugin/reader/dorisreader` even though the module is in the reactor. Release and local distributions now contain all 66 reactor plugins.
- Docker (#1662): the published image is now built from the same assembled `addax-<version>/` tree as the GitHub release archive instead of being compiled again inside the Docker build, and a plain `docker build .` from a clone still builds from source. The release job no longer rebuilds the distribution inside the Docker build.
- YAML examples (#1674): the `oracle2txt` and `stream2hdfs` examples stored the field delimiter as a raw `0x01` byte, which SnakeYAML rejects with "special characters are not allowed". The four affected files use the escaped `"\u0001"` form and now load.
- Security (#1700): Guava 32.0.1-jre → 33.7.2-jre for CVE-2026-102554 — a small Java-serialized payload could force a multi-gigabyte allocation while deserializing `CompactHashMap`/`CompactHashSet`/`MapMakerInternalMap`, crashing the JVM with `OutOfMemoryError`.

## 🧪 Testing

- The end-to-end suite was trimmed to the core database and file cases (#1671): the DuckDB, S3 (moto) and Elasticsearch cases and their harness pieces were removed so the suite stays small enough to be read and trusted and needs neither a Python virtualenv nor an external cluster in CI. It now has 20 cases (010–190, `200_sqlite2sqlite`, `260_hdfsreader_roundtrip`), all green locally with no skips. The DuckDB, S3 and Elasticsearch plugins themselves are untouched.
- New case `200_sqlite2sqlite` (#1706): ten PK splits, legacy TEXT and INTEGER-epoch DATETIME values, a scale-less NUMERIC target and a DECIMAL column whose fraction would be lost if the reader typed it from the current row.
- New reproducible performance harness under `e2e/perf` (#1689): a deterministic 2M-row MariaDB fixture, scenario jobs (MySQL → HDFS text/parquet/ORC, MySQL → local text/ORC, MySQL → MySQL, stream → HDFS/sink), a baseline runner with JFR/GC capture, a channel sweep and a data-phase report. The measured baseline report is linked from both READMEs; results are git-ignored.

# Addax 6.3.0（中文版）

Addax 6.3.0 是一个 minor 版本:重构了 transformer 的加载、校验和参数处理,移除了 `addax.sh` 内置的日期变量,修复了 channel 容量小于交换批次时永久挂起的问题,恢复了被回归破坏的原生 transformer,修正了写入计数器,保证 SQLite 的 DECIMAL 小数和 DATETIME 文本在读写往返后不丢失,并保留 DATETIME 写入 ORC 字符串列时的时间部分;另有 36 项依赖更新。端到端套件精简为核心数据库与文件用例(20 个),并新增了可复现的性能基线工具。

版本号定为 `6.3.0` 而不是 `6.2.1`:本次发布包含新功能和向后不兼容的变更,按 [版本方案](https://github.com/wgzhao/Addax/blob/master/README.md#-versioning-scheme)属于 minor 升级。

## ⚠️ 破坏性变更

### 1. `addax.sh` 不再计算日期变量 (#1715)

启动脚本过去会注入十个系统属性:`curr_date_short`、`curr_date_dash`、`curr_datetime_short`、`curr_datetime_dash`、`biz_date_short`、`biz_date_dash`、`biz_datetime_short`、`biz_datetime_dash`、`biz_datetime_0_short` 和 `biz_datetime_0_dash`。其中 `biz_*` 固定取“前一个自然日”,在周末、节假日、T+0 任务和历史补数场景下都是错的;而且注入的 `-D` 参数排在用户的 `-p` 之后,无法被覆盖。

日期计算和注入逻辑已删除。日期变量改由调用方负责:经 addax-admin 调度时由管理端按任务业务日填充,直接运行 `addax.sh` 时必须显式传入。

- **迁移方式:** 用 `-p` 传入任务引用的每个变量,例如 `-p "-Dbiz_date_short=20260101"`(每个变量一个 `-D`,写在同一段 `-p` 字符串里)。未解析的占位符会原样保留,所以升级后仍在引用 `${biz_date_short}` 的作业会把字面文本写进 SQL 或路径——升级前请检查所有使用 `${curr_*}` / `${biz_*}` 的作业。
- `AGENTS.md` 和 `SKILL.md` 已更新为新约定。

## ✨ 新特性

### 1. Transformer 加载、校验和参数处理重构 (#1688)

Transformer 模块过去把配置错误当作逐条记录失败来处理:参数缺失或格式错误的 transformer 会把每一行都变成脏数据而不是让作业失败;用户 transformer 的加载器按工作目录解析 `transformer.json`;`dx_null_to_default` 从未收到参数;`dx_pad` 在填充串为空时会永久挂起;每个内置 transformer 还会为每条记录重新解析一次位置参数。

- **命名参数。** 五个内置 transformer 支持命名形式:`dx_substr`(`idx`、`pos`、`length`)、`dx_pad`(`idx`、`flag`、`length`、`chr`)、`dx_replace`(`idx`、`pos`、`length`、`str`)、`dx_filter`(`idx`、`operator`、`expr`)和 `dx_map`(`idx`、`operator`、`value`)。例如 `{"name": "dx_pad", "parameter": {"idx": 0, "flag": "l", "length": 8, "chr": "*"}}`。旧的 `columnIndex` + `paras` 形式继续可用,但每个 transformer 名只打印一次弃用告警;同一个 transformer 混用两种形式会在启动时失败。
- **启动时校验。** 参数每次执行只解析和校验一次,不再逐条记录解析。参数缺失、未知或自相矛盾时,作业在调度任何 task 之前就失败,并给出 transformer 名和期望的参数形式,而不是整轮运行都产生脏数据。
- **只编译一次。** Groovy 代码和正则表达式在作业启动时编译。`dx_groovy` 只能调用一次(此前已有文档说明,现在会强制校验)。
- **用户 transformer。** `transformer.json` 不再按工作目录解析:注册表只加载作业引用的 transformer 目录,一次性校验类(public、非抽象、public 无参构造),失败时报告 transformer 名和路径,而不是静默跳过。加载前后的线程 context classloader 也会正确恢复。
- `dx_null_to_default` 现在能收到参数,并要求配置 `parameter.column`;`dx_pad` 不再因空填充串挂起。
- 被 transformer 过滤的记录单独计数,不再和脏数据混在一起。
- 新增可直接运行的示例:`transformer_named_demo.json` 和 `transformer_legacy_demo.json`;同时更新了 `transformer_demo.json`、`transformer_groovy.json` 和 `transformer_null_to_default.json`。

## 🐛 修复

**数据正确性**

- `sqlite` (#1706): JDBC 驱动按游标当前行的存储类推断列类型,主键切分从整数值开始时 DECIMAL/NUMERIC 的小数部分会被截断;3.54.1.0 驱动还把 DATETIME 映射为 `Types.TIMESTAMP`,会把原本的 TEXT 写成 INTEGER 毫秒时间戳。现在 reader 按声明的列类型处理 DECIMAL/NUMERIC,writer 用 `setBigDecimal` 绑定 DECIMAL/NUMERIC、把 `Types.TIMESTAMP` 写成带毫秒的 TEXT,小数和 DATETIME 文本在读写往返后保持不变。reader 还为 username/password 提供默认值,从插件模板复制的作业可以直接启动。
- `hdfswriter`、`s3writer` (#1707): ORC 字符串目标把所有非 TIME 的日期列都渲染成 `yyyy-MM-dd`,DATETIME(例如 `mongodbreader` 读出的 BSON 日期)被静默截断成只含日期的字符串。现在 DATE/DATETIME 统一走列格式化器(`common.column.dateFormat` / `datetimeFormat` / `timeZone`),与文本、parquet writer 一致;DATE 仍只输出日期,TIME 保留纳秒路径。此类 ORC 文件的下游消费者将看到时间部分。
- `core` (#1673): 写入端把从 channel 取出的每条记录都计入,包括 terminate 标记,导致 task 报告的写入数比读取数多一——4 个 task 搬运 400 行会报告 `writeReceivedRecords=404`。现在完整写入的作业满足 `writeSucceedRecords == readSucceedRecords`;三处 channel 等待都会恢复线程中断状态,并统一抛出 `AddaxException`,不再丢失中断状态或抛裸 `IllegalStateException`。
- `core` (#1664): 回归导致原生 transformer `dx_substr`、`dx_replace`、`dx_map`、`dx_filter` 全部不可用——它们要求 Groovy 代码,`columnIndex`/`paras` 被静默丢弃,连自带的 `transformer_demo.json` 都无法运行。现在恢复了回归前的语义:只有 Groovy 函数消费 `code`/`codeFile`,其余 transformer 要求 `columnIndex` 并接受可选 `paras`,缺少 `columnIndex` 时给出明确错误。
- `plugin-paimonwriter` (#1679): 所有经过 Hadoop 的 warehouse 都因 `addBlock` 路径抛出 `NoClassDefFoundError: com/google/protobuf/ServiceException` 而失败——Paimon 在自己的 Hadoop 依赖中排除了 protobuf,插件里一个都没有。现在像 `hdfswriter`、`hdfsreader`、`icebergwriter`、`s3writer` 一样打包 `protobuf-java`(3.25.5);此前只有 file:// warehouse 可用。

**可靠性**

- `core` (#1668): 当 `core.transport.channel.capacity` 小于交换批次(默认 32)时,`MemoryChannel` 要等整个批次都放得下才入队,于是永远放不进去:reader 线程永久阻塞,作业停在 "Total 0 records" 且不报错。现在按记录逐条入队,每条都等待队列和字节预算的空间,并在每条之后通知消费者,不再依赖 200 ms 轮询超时。单条记录超过字节预算时直接抛 `OVER_LIMIT_ERROR`,不再永久等待;`clear()` 会连同队列一起重置字节计数。
- `core` (#1670): 失败重试可能在上一轮尝试仍在写入时启动(造成重复写入),而当重试预算刚好耗尽时,等待会退化成无界的 `join(0)`。现在每次尝试运行在独立的两 worker executor 上,只有 executor 终止才算本次尝试结束,框架因此保证重试开始前上一轮已真正退出;下一个 task 也会立即派发,不再等 100 ms 心跳。
- `core` (#1667): 插件入口类在作业启动时解析并校验——类必须存在、继承 `Reader.Job`/`Reader.Task` 或 `Writer.Job`/`Writer.Task`、public、非抽象、嵌套时 static,并声明 public 无参构造。插件声明有问题时,作业在任何 task 启动前就失败,错误信息包含插件名、`plugin.json` 路径和尝试加载的类名,而不是运行中途抛裸堆栈。
- `core` (#1665): `job.content` 在解析阶段统一规范为 dict;旧的单元素数组形式继续可用,多元素数组会告警并取第一个元素,空数组直接失败;切分后的 task 列表移到内部键。
- 不改变行为的内部清理:task 状态机集中到不可变的 `TaskState`(#1672);删除无用的单记录 channel API 和 `RecordExchanger`(#1669);框架配置键改用类型化的 `JobConfig`/`TaskConfig` 视图读取(#1666);删除从未实现的分布式模式遗留的无用抽象(#1663)。

**脚本、打包与 CI**

- `install_plugins.sh` (#1695): 校验插件名和版本,安装到 `libs/` 并采用分阶段原子替换和备份,恢复所需的传递依赖,校验元数据和引导的 Maven 归档,并新增 `force`、加锁、汇总、严格的 release 校验和以及交互式 Maven 输出。已有的 `lib/` 安装会重新安装到 `libs/`。同一提交还把 Elasticsearch writer 的模板资源改名,使基于模板的作业生成能找到 `plugin_job_template.json`。
- 发行版 (#1719): 根 `package.xml` 漏掉了 `dorisreader`,导致 `-Pdistribution` 产出的目录里没有 `plugin/reader/dorisreader`,尽管该模块在 reactor 中。现在发布版和本地发行版都包含全部 66 个 reactor 插件。
- Docker (#1662): 发布镜像改为直接使用与 GitHub Release 归档相同的 `addax-<version>/` 目录树,不再在 Docker 构建中重新编译一遍;直接 `docker build .` 仍是从源码构建。发布作业不再在 Docker 构建中重新编译发行版。
- YAML 示例 (#1674): `oracle2txt` 和 `stream2hdfs` 示例把字段分隔符存成裸 `0x01` 字节,SnakeYAML 会报 "special characters are not allowed"。四个受影响的文件改用转义的 `"\u0001"` 形式,现在可以正常加载。
- 安全 (#1700): Guava 32.0.1-jre → 33.7.2-jre,修复 CVE-2026-102554——反序列化 `CompactHashMap`/`CompactHashSet`/`MapMakerInternalMap` 时,很小的 Java 序列化载荷就能强制申请数 GB 内存,导致 JVM 以 `OutOfMemoryError` 崩溃。

## 🧪 测试

- 端到端套件精简为核心数据库与文件用例 (#1671):删除了 DuckDB、S3(moto)和 Elasticsearch 用例及只为它们存在的 harness 组件,让套件保持小而可信,CI 也不再需要 Python 虚拟环境或外部集群。现有 20 个用例(010–190、`200_sqlite2sqlite`、`260_hdfsreader_roundtrip`),本地 20/20 全绿、无跳过。DuckDB、S3 和 Elasticsearch 插件本身未改动。
- 新增用例 `200_sqlite2sqlite` (#1706):覆盖 10 个主键切分、遗留的 TEXT 与 INTEGER 毫秒 DATETIME 值、无小数位的 NUMERIC 目标,以及一个若按当前行推断类型就会丢失小数的 DECIMAL 列。
- `e2e/perf` 下新增可复现的性能工具 (#1689):确定性的 200 万行 MariaDB 数据集、各类场景作业(MySQL → HDFS text/parquet/ORC、MySQL → 本地 text/ORC、MySQL → MySQL、stream → HDFS/sink)、带 JFR/GC 采集的基线运行器、channel 扫描和数据阶段报告。实测基线报告已从两个 README 链接;结果文件被 git 忽略。

## ⬆️ 升级方式

- **发行版:** `addax-6.3.0.tar.gz` 与 `addax-6.3.0.tar.gz.sha256sum.asc`,解压前请校验。
- **Docker:** `wgzhao/addax:6.3.0`(Docker Hub)与 `quay.io/wgzhao/addax:6.3.0`。
- **Maven Central:** `com.wgzhao.addax:addax-core:6.3.0`。
- **升级前请检查:**
  - 直接在 `addax.sh`(或 addax-admin 之外的调度器)中运行且引用 `${curr_*}` / `${biz_*}` 的作业——改用 `-p` 传入;
  - 把 ORC 字符串文件中的 DATETIME 列按“仅日期”解析的下游消费者;
  - 仍使用 `columnIndex` + `paras` 配置 transformer 的作业——仍可用,但建议迁移到命名形式,且不要在同一个 transformer 中混用两种形式;
  - 用 `install_plugins.sh` 安装过插件的环境——已有的 `lib/` 安装会在重新安装时迁移到 `libs/`。
- 插件文档:<https://github.com/wgzhao/addax-docs>
